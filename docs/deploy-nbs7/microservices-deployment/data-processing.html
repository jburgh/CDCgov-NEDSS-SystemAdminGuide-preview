    Deploy Real Time Ingestion (RTI) data processing for NBS 7

    This page walks through deploying the Real Time Ingestion () data processing service using the data-processing-service from the NEDSS-Helm repository for NBS version 7.13.

    On this page

    1. Overview
    2. Prerequisites
    3. Deploy RTI using Helm
    4. Next steps

    Overview

    Real Time Ingestion (RTI) is a microservice that picks up data after it has been ingested and queued in the NBS Interface table. It processes each record and either marks it as successful or delivers it to the NBS queue. Events are handled through . There is no direct user interaction with RTI. RTI is triggered through the data ingestion ELR endpoint and can work alongside the ELR importer batch job or replace it, providing near-real-time ELR processing without requiring a -managed batch job.

    Prerequisites

    This page assumes you’ve completed Before you begin for the microservices phase and each microservice deployment page before this one, in order. The page immediately before this one is the NBS Gateway deployment.

    Have your database credentials, Kafka endpoints, and client secret available. See the Helm values reference and Import service clients and retrieve secrets if you need help determining any values.

    Deploy RTI using Helm

    Complete the following steps to deploy the ‘data-processing-service’ Helm chart from the charts/data-processing-service/ directory of your cloned NEDSS-Helm repository:

    1. Confirm that a entry for the data ingestion endpoint was created and points to the active Network Load Balancer () provisioned during core services deployment.

    2. Set the auth user. RTI uses a valid NBS user to process data. Set nbs.authuser to a valid user from ODSE.Auth_User:

      nbs:
  authuser: "superuser"

      To find valid auth users, query the ODSE database. Replace NBS_ODSE if your database uses a different name:

      SELECT * FROM NBS_ODSE.dbo.Auth_user;

    3. In the data-processing-service/values.yaml file, search for EXAMPLE and fill in your environment-specific values for the connection, data ingestion ingress domain, Kafka cluster endpoint, and Keycloak client. The dbserver value is the database server endpoint only; do not include the port number. The Helm values reference lists the values to use.

    4. Install the data processing service:

      helm install "data-processing-service" ./data-processing-service -f ./data-processing-service/values.yaml

    5. Confirm the pod is running before continuing:

      kubectl get pods
    6. See RTI API testing and integration for API testing guidance.

    7. Validate the service by running the following commands and verifying that the output is similar to what is shown. These commands require the jq JSON processor to be installed.
